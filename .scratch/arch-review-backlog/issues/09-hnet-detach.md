# 09: The detach of an H-Net cache follows from its traversal

Status: resolved

Blocked by: None

> *This was generated by AI during triage.*

From the review of ticket `08-cache-traversal.md`. That ticket made the `CacheTensors`
traversal the one hand-written list of the fields of a cache, and it put the H-Net
impls out of scope. This ticket removes the field list that remains in H-Net.

## Agent brief

**Category:** enhancement

**Summary:** Give one detach that follows from `CacheTensors`. `CacheStack::detach` and
`HNetCaches::detach` both call it. So `HNetCaches::detach` lists no field.

**Current behaviour:**

- `HNetCaches::detach` (`src/modules/hnet/cache.rs`) writes its own backend hop. It
  names each field of `HNetStageCache` and of `RouterCache`: `encoder`, `router.last_bd`,
  `router.seen_b`, `smooth_bd` and `decoder`. It has two closures, `hop` (rank 2) and
  `hop1` (rank 1), with the same body: `lift(t.inner(), &t.device())`.
- The `CacheTensors` impl of `HNetStageCache` lists the same fields again. So a new
  field of `HNetStageCache` or of `RouterCache` can appear in `zip_tensors` and be
  missing from `detach`. The code compiles, and the new field keeps its graph after a
  detach.
- `CacheStack::detach` (`src/modules/cache.rs`) builds its round trip inline for each
  slot: `cache_device`, then `cache_to_inner`, then `cache_from_inner`.
- No test checks `HNetCaches::detach`. burn-mamba calls it in
  `examples/hnet-stories/training.rs` (`detach_caches`).

**Desired behaviour:**

- burn-stack gives one detach for each type that implements `CacheTensors`. It is a
  free function in `src/modules/cache.rs`, beside the hop of ticket 08. It is the round
  trip: `cache_device`, `cache_to_inner`, then `cache_from_inner` onto that device. The
  agent selects the name. A cache type cannot override it.
- `CacheStack::detach` calls it on each slot. Each slot still goes back onto its own
  device, with the checkpointing strategy of that device.
- `HNetCaches::detach` calls it on the whole cache. It names no field. It requires
  `E::Caches: CacheTensors` and `M::Caches: CacheTensors`, as `HNet::step` does.
- Each tensor of an H-Net cache goes back onto the device of the cache. All the tensors
  of one H-Net cache are on one device. So the result is the same as the per-tensor
  `hop` of today.
- The docs of `HNetCaches::detach`, of `CacheStack::detach` and of the module header
  of `src/modules/hnet/cache.rs` describe the code as it is.
- The crate goes to the next minor version, because `HNetCaches::detach` gets a new
  bound. The commit message states the break.

**Test seam:** one module alone, `src/modules/hnet/tests.rs` (see
`docs/agents/testing.md`). Write the new test first. It passes on the code of today, and
it stays green through the change.

**Acceptance criteria:**

- [ ] The body of `HNetCaches::detach` names no field of `HNetStageCache`,
      `RouterCache` or `HNetCaches`.
- [ ] `rg 'lift\(' src/modules/hnet/` finds nothing.
- [ ] A new test in `src/modules/hnet/tests.rs` runs an H-Net with at least one stage,
      on a plain device and on an autodiff device with gradient checkpointing. The
      test visits each tensor of the cache through `zip_tensors`. After
      `HNetCaches::detach`, each tensor keeps its values. It has the autodiff flag and
      the checkpointing strategy of the device.
- [ ] The existing tests of `detach`, `grad_horizon`, capture and H-Net pass, with no
      change to an expected value or a tolerance.
- [ ] The checks and tests of this repo pass, as `CLAUDE.md` gives them, with no
      warnings.
- [ ] `Cargo.toml` has the next minor version.

**Constraints:**

- burn-mamba builds against its pin. Do not enable the `[patch]` of burn-mamba for
  this ticket. Each cache type of burn-mamba implements `CacheTensors` already, so the
  new bound does not break its `hnet-stories` example.
- burn-mamba ticket `11-cache-traversal.md` pins "the commit of ticket 08, or later".
  If this ticket lands before ticket 11, ticket 11 can pin this commit. Push the commit
  when the ticket is complete and reviewed.

**Benches:** none. No tensor op changes.

**Out of scope:**

- A `CacheTensors` bound on `Block::Caches`. It would remove the eight
  `E::Caches: CacheTensors` / `M::Caches: CacheTensors` where clauses of H-Net and of
  `examples/tiny_stories/sample.rs`. That is a separate decision.
- The `CacheTensors` impls of H-Net. They stay as they are.
- burn-mamba and its pin.
