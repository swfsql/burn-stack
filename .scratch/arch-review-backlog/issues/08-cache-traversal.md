# 08: The cache traversal is the one field list, and a block gives one zero cache

ticket asked to split its step 2 by repo. This ticket is the burn-stack half. The

## Agent brief

**Category:** enhancement

**Summary:** Derive the backend hop of a cache from its `CacheTensors` traversal, so
that the traversal is the only hand-written list of the fields of a cache. Replace the
two zero-cache methods of `Block` with one method that gives one zero cache.

**Current behaviour:**

- `CacheStack` has six required methods. Three of them move a cache across the
  backends: `cache_to_inner`, `cache_from_inner` and `cache_device`. Each cache type
  writes them by hand, and each one lists every tensor field again. `CacheStack::detach`
  and `Layers::grad_horizon` call them.
- `CacheTensors` is a separate trait. Its `zip_tensors` is a second hand-written list of
  the same fields. Only a captured step and H-Net require it.
- So a field can appear in `zip_tensors` and lack its `.inner()` in `cache_to_inner`. The
  code compiles, and the error shows only when a cut crosses a config that holds this
  field.
- `Block` has `zero_caches_3d(&x, n_virtual)` and `zero_caches_2d(&x, n_virtual)`. Every
  impl (`RefBlock`, and the three families of burn-mamba) reads only the batch and the
  device of `x`, and gives the same caches for both. H-Net allocates zero tensors only to
  give these calls a size. `Layers`, `BidiLayers` and H-Net call them. `Layers` and H-Net
  each have a pair of public `zero_caches_2d`/`zero_caches_3d` methods.

**Desired behaviour:**

- `CacheStack` requires that its `Cache` implements `CacheTensors`.
- `cache_to_inner`, `cache_from_inner` and `cache_device` are not methods of `CacheStack`.
  burn-stack gives them for each type that implements `CacheTensors`:
  - They follow from `zip_tensors`. A map is the zip of a cache with its clone. It costs
    one refcount per tensor per cut, and no tensor op.
  - A cache type cannot override them, because an override is a second field list. Use
    free functions, or an extension trait with a blanket impl. The agent selects the form
    and the names.
  - `cache_from_inner` lifts each tensor with `lift`, as today.
  - `cache_device` panics with a message on a cache that holds no tensor. Its doc gives
    the rule: a per-layer cache holds at least one tensor.
- `CacheStack::detach` and `Layers::grad_horizon` keep their behaviour: each slot goes
  back onto its own device, with the checkpointing strategy of that device.
- The doc that gives the reason for a hand-written list (`Module::map` does nothing on a
  plain `Tensor` field) moves to `CacheTensors`. The traversal is now the one list.
- `Block::zero_cache(&self, batch, device) -> Self::Cache` replaces `zero_caches_3d` and
  `zero_caches_2d`.
  - `Layers`, `BidiLayers` and H-Net build the `n` slots with `CacheStack::from_slots`,
    with one call of `zero_cache` for each slot. So each slot has its own buffers, which a
    captured step needs.
  - In `Layers` and in H-Net, one public zero-cache method replaces each 2-D/3-D pair. It
    takes the batch and the device.
  - H-Net allocates no tensor only to size a zero cache.
- `RefBlock` and `RefCaches` follow. Their hand-written hop is gone.
- The crate goes to the next minor version, in the first breaking commit. The commit
  message states the break: the three hop methods leave `CacheStack`, `CacheStack`
  requires `CacheTensors`, and `Block::zero_cache` replaces the two zero-cache methods.
