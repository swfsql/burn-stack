## Agent brief

**Category:** enhancement

**Summary:** Give each residual scheme one residual join inside `Residuals`, and give
the backend hops of the gradient horizon one private owner. The behaviour does not
change.

**Current behaviour:**

- `Residuals` is an enum with no behaviour. Each loop holds the rule of each scheme in
  its own `match`:
  - The Multi-Gate branch has three copies: in `Layers::forward_rows`, in
    `Layers::cascade` and in `BidiLayers::forward`.
  - The seed of the residual streams has three copies: `multi_gate_streams_seed` of
    `Layers`, the stream sets of `cascade`, and `multi_gate_streams_seed` of
    `BidiLayers`.
- The backend hop has two copies, one in `forward_rows` and one in `cascade`. Each copy
  holds these parts:
  - the start of an untracked span and its cut
  - the hop of the cache slots (`cache_to_inner`, `cache_from_inner`)
  - the choice of the layer view: `self`, or the `Module::valid` copy of the stack
  - the lift at the top of the stack
- The two loops refer to each other in 10 comments, such as "as in `forward`".
- Under `Residuals::Standard`, a suppressed skip moves `x` into the layer with no clone.
  A clone keeps the input alive through the block call and raises the GPU peak.
- The class splice runs before each loop, not inside it. This ticket does not move it.

**Desired behaviour:**

1. **The residual join.** `Residuals::join` (crate-private) holds the rule of each
   scheme at one layer.
   - It takes the residual-streams value, the position of the layer and a closure. The
     position holds the virtual index, the MGR module index and the `first`/`last`
     suppression flags.
   - The closure runs the layer on the input. It returns the output of the layer and
     one more value of a generic type, for example the cache.
   - The join returns the new residual-streams value and that extra value.
   - The scheme decides whether it clones the input before it calls the closure. Under
     a suppressed skip of Standard, and under MGR, the input moves into the closure
     with no clone.
   - The join is generic over the token rank `R` and the stream rank `S`, with an
     assert that `S == R + 1`. `forward_rows` and `BidiLayers::forward` use ranks 3
     and 4. `cascade` uses ranks 2 and 3, once for each token.
   - `BidiLayers::forward` gives the module index of the pair, as it does now.
   - The seed of the residual streams is one function.
2. **The residual-streams value.** It holds the token (the input of the next layer)
   and, under MGR, the residual streams. Name it from the glossary terms.
3. **The carry belongs to the scheme.**
   - The scheme has two carry methods. One of them runs at the start of an untracked
     span and gives the carry. The other one runs at the cut and adds the carry back.
   - The carry is a type of the scheme. Both methods take the residual-streams value
     by move, so ticket 10 can keep its span state inside that value.
   - The current rule stays. Under Standard, the carry of the token returns to the
     token. Under MGR, the carry of the pooled token returns to the token and to
     every residual stream. Ticket 10 changes the MGR rule.
4. **The backend hop has one owner.** A private type in `layers.rs` owns everything
   that crosses either end of an untracked span:
   - the tracked mask of `grad_tracked`
   - the `Module::valid` copy of the stack, and the choice of the layer view for each
     virtual layer
   - the device of the stack
   - the carry
   - the hop of the cache slots
   - the lift at the top of the stack

   `forward_rows` gives it one residual-streams value. `cascade` gives it one value for
   each token of its stream. The owner knows no scheme. It calls only the two carry
   methods.
5. **The home.**
   - A new module `src/modules/residuals.rs` holds `Residuals`, `ResidualsConfig`, the
     join, the residual-streams value and the carry methods.
   - `multi_gate.rs` keeps the MGR math: `MultiGateResidual`, `MultiGate` and
     `MultiGateResidualConfig`. `mix_pool` and `append_pool` become `pub(crate)`, so
     that the join can call them at each rank.
   - `MultiGateResidual::{forward, step, accumulate, accumulate_step}` stay public
     with the same signatures. They become thin wrappers.
   - The paths `modules::Residuals` and `modules::ResidualsConfig` stay. The ticket
     removes the paths `modules::multi_gate::{Residuals, ResidualsConfig}`, with no
     re-export. This breaks the public API, so `Cargo.toml` goes from 0.41.0 to
     0.42.0 in the first breaking commit.
6. The public interfaces of `Layers` and `BidiLayers` do not change.

**Tests:**

- A new `src/modules/residuals/tests.rs` (the "one module alone" seam). Its tests use
  no block:
  1. Standard: a middle layer gives the output plus the input. A layer with a

### Implementation notes

> *This was generated by AI during implementation.*

- The position of a join is `JoinAt { virtual_idx, real_idx, first, last }`. The join
  computes the MGR module index with `MultiGate::module_index(virtual_idx, real_idx)`.
  A caller that gave the module index itself would need `per_virtual`, so it would match
  on the variant. `BidiLayers::forward` gives the virtual and the real index of the pair.
- The two carry methods are `Residuals::open_span` and `Residuals::close_span`. The
  glossary avoids "carry" alone. `open_span` takes the straight-through carry on the
  autodiff side, then moves the value to the inner backend. `close_span` lifts the
  value, then adds the carry back. So the order of each end of a span is in one function.

  The owner `BackendHop` (in `layers.rs`) decides where each end is, and it hops the
  cache slots. At the top, it drops the residual streams (`ResidualStreams::into_top`)
  and calls `close_span`. This matches the base, which lifted only the token there.
- For ticket 10: `open_span` and `close_span` run on the `Residuals` of the tracked
  stack, not on the `Module::valid` view. The join of an untracked layer runs on the
  view. So a per-stream factor can update on the inner backend inside the join. For
  the same reason, `close_span` must take the aggregator weights from the value, not
  from the MGR parameters. `StraightThroughCarry<R, S>` has the stream rank `S` for
  the per-stream carries of ticket 10.
- `pub mod residuals` adds the path `modules::residuals::{Residuals, ResidualsConfig}`,
  in the pattern of `pub mod multi_gate`.
- `rg multi_gate_streams_seed src docs` finds nothing. From the repo root, `rg` also
  finds the text of this ticket.
- The review (`tmp/arb02/review-standards.md`, `tmp/arb02/review-spec.md`) found no
  error in the code. The ticket fixed its doc and test findings. Two smells stay: the
  `JoinAt` of `BidiLayers::forward` repeats the shape of `Layers::join_at`, with pair
  indices. And `forward_rows` puts its one value in a `Vec`, because one `BackendHop`
  serves both loops.
