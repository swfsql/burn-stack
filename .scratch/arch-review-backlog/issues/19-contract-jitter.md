# 19: Each block contract moves the weights away from their init

Status: ready-for-agent

Blocked by: `../burn-mamba/.scratch/arch-review-backlog/issues/19-initial-state-zero-cache.md`

> *This was generated by AI during the triage of burn-mamba ticket 19.*

**Problem:** Three block contracts add noise to each float parameter before they run
the block (`Jitter`): `record_round_trip_keeps_the_block`,
`json_round_trip_keeps_the_config` and
`untied_stack_equals_the_stack_of_its_application_views`. The other contracts that run
a block use it as its config builds it. A parameter that starts at zero then has no
effect in them. So these contracts cannot see a call that ignores such a parameter.

Burn-mamba ticket 19 found a bug of this class. The Mamba-2 `step` did not read the
learnable initial state, which starts at zero. The forward read it. No contract failed,
because no contract gave that state another value.

## Agent brief

**Category:** enhancement

**Summary:** Each block contract that runs a block or a stack adds noise to its float
parameters first, as the three contracts above do.

**Current behaviour:** These contracts run the block or the stack with the parameters
of the init:

- `forward_equals_step_unrolled`
- `forward_splits_into_windows_through_the_cache`
- `padded_rows_equal_each_row_alone`
- `packed_segments_equal_each_segment_alone`
- `cache_traversal_moves_every_field`
- `cut_keeps_the_outputs_and_the_caches`

The two Muon contracts read the names and the shapes of the weights. They run no block.

**Desired behaviour:**

- Each contract of the list above applies `Jitter` to the block or to the stack after
  its build, and before its first call.
- When a contract compares two blocks or two stacks, both sides hold the same
  jittered parameters. For example, the stack with a cut and the stack with no cut of
  `cut_keeps_the_outputs_and_the_caches` hold the same values.
- The doc of each changed contract says that noise moves each float parameter away
  from its initial value first. The doc of `Jitter` gives the reason: a parameter at its
  init value can hide a call that ignores it.

**Key interfaces:**

- `Jitter` keeps its noise: normal, standard deviation 0.1.
- The signatures of the contracts do not change.

**Constraints:**

- Do not change a tolerance or an expected value.
- If a contract fails on `RefBlock` with the noise, stop. Report the contract and the
  difference under `## Comments`.
- The real families run these contracts in their own crates. Before the commit, run the
  block contracts of burn-mamba against this change:
  - Use the `[patch]` of the burn-mamba `Cargo.toml`. Its
    `docs/agents/issue-tracker.md` gives the rules of the pin.
  - Run `cargo test --lib -- --test-threads=1 block_contract` in burn-mamba.
  - Do not commit in burn-mamba, and turn its `[patch]` off again.
  - If a setting fails, stop. Report the setting, the contract and the difference
    under `## Comments`. Do not change a tolerance in either repo.
- This change does not break the public API. The version does not change.
- The prose check of `scripts/check.sh` compares the hard violations of each changed
  file with `origin/main`.

**Acceptance criteria:**
