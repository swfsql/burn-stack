# 13: One tiling of the untied parameters, from `untied_params`

Status: ready-for-agent

Blocked by: None

From the architecture review of 2026-11-16. Line numbers are those of burn-stack
commit `b198fa5` and burn-mamba commit `7807d31b`. The review compiled nothing.

**Files:** `src/utils/untied.rs`, `src/modules/mod.rs` (`BlockConfig::init_block`),
`src/modules/layer.rs:76-105`, `src/modules/layers.rs:932-945`,
`src/modules/bidi.rs:417-430`, `src/reference.rs:217-300`,
`../burn-mamba/src/mamba3/mamba3.rs:735-771,1255-1500`,
`../burn-mamba/src/mamba2/mamba2.rs`, `../burn-mamba/src/mamba1/mamba1.rs`,
`../burn-mamba/src/family/adapters.rs`.

**Problem:** Each untied parameter has its axis in two lists. `untied_params` gives it
in `UntiedParam::new(&param, axis)`, and `view` and `retie` read that list. The init
does not read it: `init_applications` calls `untied::tile(param, axis, copies(…))` for
each parameter by hand. The two lists have about 55 call sites: Mamba-3 20, Mamba-2
17, Mamba-1 11, `Layer` 3, `RefBlock` 4. `copy_len` catches a wrong axis only when
the length of that axis is not a multiple of the count. So `init_block` takes
`n_applications`, and each family passes the count to each parameter.

**Direction:** `Layer::init` tiles the layer and its block in one pass over
`untied_params()`. The mapper of `untied::retie` already does this by `ParamId`: it
narrows to the first copy and repeats it along the axis. `init_block` loses
`n_applications`, a family builds the tied block, and the three `init_applications`
go. A new untied parameter then needs one line.

**To check at triage:**

- The order of the random draws stays, so an untied stack still starts equal to the
  tied stack.
- `in_proj_tail` of Mamba-3 and Mamba-2: its weight has the copies along axis 1, and
  its bias along axis 0. Its width at the build is that of one application.
- `require_grad` of the tiled leaf (see the comment in the `Retie` mapper).

**ADR:** ADR-0008 stays. The copies stay side by side on an existing axis.

**Related:** `.scratch/untied-application-axis/issues/01-application-axis.md` changes
the layout of the copies. This ticket makes that change smaller, because the layout
then has one writer.
`../burn-mamba/.scratch/untied-kalman-tropical/issues/01-untied-kalman-and-tropical-tensors.md`
adds untied tensors to the block contracts.

Split this ticket by repo at triage.

## Agent brief

**Category:** enhancement

**Summary:** The layer tiles each untied parameter from `untied_params`, in one pass.
A block config builds the block for one application.

**Current behaviour:**

- `BlockConfig::init_block(&self, n_applications, device)` builds a block with the
  copies of each untied parameter. Each family tiles each parameter by hand with
  `untied::tile(param, axis, n_applications)`, and it gives the axis again in
  `Block::untied_params`.
- `Layer::init` tiles the pre-norms that `LayerUntied` names in the same way.
- `RefBlockConfig::init_applications(n_applications, device)` tiles `gate_proj` and
  `decay_raw`. `RefBlockConfig::init` calls it with 1.
- The contract `untied_stack_equals_the_stack_of_its_application_views` first runs
  `untied_params_name_each_tiled_tensor`. It compares `init_block(1)` with
  `init_block(3)`.

**Desired behaviour:**

- A block config builds the block for one application. The init of a family calls no
  `tile`.
- `Layer::init` builds the layer with its tied block and its tied pre-norms. Then it
  tiles each parameter of `Layer::untied_params` once, along its axis.
- Each application of an untied parameter starts from the same draw, as before.
- A real layer with one application keeps its stock shape. Its lazy parameters stay
  lazy.
- At a fixed seed, a `RefBlock` stack gives the same values as before.

**Key interfaces:**

- **`BlockConfig::init_block(&self, device: &Device) -> Self::Block`**: it has no count
  of applications. Its doc says that the block holds one copy of each parameter, and
  that the layer tiles the untied parameters.
- **`untied::tile<M: Module>(module: M, params: &[UntiedParam], n_applications: usize) -> M`**:
  - It repeats each parameter of `params` `n_applications` times along its axis.
  - With `n_applications == 1`, it gives `module` back unchanged.
  - It keeps the `ParamId`, the `require_grad` flag and `is_active` of each parameter.
  - The `tile` of one parameter goes.
- **`untied::retie`** keeps its signature. `retie` and `tile` share one private mapper.
  The mapper takes copy 0 of the stored tensor and repeats it. For `tile`, the
  stored tensor is copy 0.
- **`Layer::init`** takes the tied block and the count. It calls
  `tile(layer, &layer.untied_params(), n_applications)` once.
- **`LayersBuilder::init`** and **`BidiLayersBuilder::init`** call
  `init_block(device)`.
- **`RefBlockConfig`**: `init_applications` goes. `init(device)` builds the tied block,
  and `BlockConfig::init_block` calls it.
- **The untied contract**:
  - `untied_params_name_each_tiled_tensor` goes, with its check of the count of
    parameters.
  - `untied_stack_equals_the_stack_of_its_application_views` returns early when
    `config.init_block(device).untied_params()` is empty.
  - The other checks of the contract do not change. Its doc loses the first part of
    its list.
- **The contract tests**:
  - `a_tiled_parameter_that_untied_params_omits_breaks_untied_stack_equals_the_stack_of_its_application_views`
    goes, with `Breach::UntiedList` and its branch in the `untied_params` of
    `BrokenBlock`.
  - `BrokenBlockConfig::init_block` loses the count. `untied_broken` stays if another
    test calls it.
- **The docs**:
  - The header of `utils::untied`: a family names its untied parameters
    (`Block::untied_params`), and the layer tiles them when it is built for several
    applications. Its first rule names the new `tile`.
  - The doc of `Block::untied_params`: the config decides which parameters are
    untied. The layer tiles them.
  - The doc of `Layer::retie`: the build starts from copies of the first application.
  - The example of `BlockConfig` in `README.md`.
  - ADR-0008, `GLOSSARY.md` and `docs/burn/autodiff-semantics.md` do not change.
