## Agent brief

**Category:** enhancement

**Summary:** Replace `utils::combined_grad` with one generic recompute node. The node
owns the autodiff wiring of a custom backward that has two outputs.

**Current behaviour:**

- `utils::combined_grad` holds `flatten_pair`, `unflatten_pair` and
  `autodiff_unflatten_pair`.
- Each caller writes the other wiring by hand: `prepare`, both `OpsKind` arms, a
  `State` struct, the gradient consume and the gradient register.
- Each caller keeps the order of `prepare`, `ops.parents` and `State` by hand. A wrong
  order compiles.
- `autodiff_unflatten_pair` is `unflatten_pair` at `B = Autodiff<B, C>`.
- All six `flatten_pair` calls discard the two lengths that it returns.
- No test reaches the wiring alone.

**Desired behaviour:** A caller gives named inputs, one `Extra` value and one op type.
The node does these steps:

1. It builds the parent array from the named inputs and calls `prepare`.
2. The tracked arm saves the inputs and `Extra`, and runs `forward`. It packs the two
   outputs into one tracked 1-D tensor, and returns two views at the output shapes.
3. The untracked arm moves the inputs into `forward`. It uses the same pack and split.
4. The backward consumes the combined gradient and splits it. It calls the backward of
   the op and registers each `Some` gradient on its parent.
5. It reads the output shapes from the results of `forward`. A caller gives no shape
   and no flat length.

**Key interfaces:** `utils::recompute_node`, under the `autodiff` feature.

```rust
pub trait RecomputeInputs<T, const N: usize>: Sized {
    fn into_array(self) -> [T; N];
    fn from_array(array: [T; N]) -> Self;
}

// `recompute_inputs!(Name { field, .. })` declares `struct Name<T>` and its
// `RecomputeInputs<T, N>` impl. It counts `N` from the fields.

pub trait RecomputeOp<B: Backend, const N: usize>: 'static {
    type Inputs<T>: RecomputeInputs<T, N>;
    type Extra: Clone + fmt::Debug + Send + 'static;

    fn forward(inputs: Self::Inputs<Prim<B>>, extra: &Self::Extra) -> (Prim<B>, Prim<B>);

    fn backward(
        d_y: Prim<B>,
        d_final_state: Prim<B>,
        inputs: Self::Inputs<Prim<B>>,
        extra: Self::Extra,
    ) -> Self::Inputs<Option<Prim<B>>>;
}

pub fn recompute_pair<B, C, O, const N: usize>(
    inputs: <O as RecomputeOp<B, N>>::Inputs<FloatTensor<Autodiff<B, C>>>,
    extra: O::Extra,
) -> (FloatTensor<Autodiff<B, C>>, FloatTensor<Autodiff<B, C>>);
```

`Prim<B>` is the float primitive of `B`. A throwaway probe compiled this shape on Burn
0.22.1, and its tests passed on `Autodiff<Flex, C>`. See
`../burn-mamba/tmp/triage-03/probe/src/lib.rs`. The probe names the trait
`RecomputePlant`. Do not use that word here: "plant" is a term of the burn-mamba
glossary (ADR-0002).

**Constraints:**

- The node type has no data. A zero-size type with a hand-written `Debug` meets the
  `Send + Debug + Sized + 'static` bounds of `Backward`. The op type needs no `Debug`.
- One generic split function serves the inner backend and `Autodiff<B, C>`.
- The untracked arm keeps its `float_cat`. `OpsPrep<UnTracked>::finish` consumes the
  prep and returns one tensor, and it registers a step on purpose. A second output
  without the cat needs a second prepare or a bare leaf.
