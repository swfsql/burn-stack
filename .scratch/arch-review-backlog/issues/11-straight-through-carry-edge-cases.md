# 11: The edge cases of the straight-through carry

Status: resolved

Blocked by: `10-mgr-straight-through-carry.md`

> *This was generated by AI during triage.*

From the triage of `02-residuals-transition.md` on 2026-11-16. Ticket 10 sets the rule
of the straight-through carry for the main case. This ticket tests that rule in each
edge case and fixes each case that fails. It stops at the suppressed skips, because
the user selects their rule.

## Agent brief

**Category:** bug

**Summary:** Test the straight-through carry in each edge case against the rule of
ticket 10, and fix each case that fails. Stop at the suppressed skips for a decision
of the user.

**Current behaviour:**

- After ticket 10, the exactness tests of the gradient horizon cover a cut at the
  bottom of the stack, with closed and with open gates.
- No test runs a cut together with `ignore_first_residual` or `ignore_last_residual`.
- No exactness test runs these cases:
  - a cut inside the stack under MGR
  - a span in which the accumulation phase ends
  - `per_virtual_layer` modules across a cut
  - the cascade of `step` and `prime` under a cut

  Some of them run in tests that compare values and check only that a gradient exists,
  for example `grad_horizon_mask_alternates_and_keeps_forward_step_parity`.

**Desired behaviour:**

Each case below gets one exactness test in the style of `assert_identity_span_is_exact`.
The untracked layers have zero transforms. The test compares two gradients: that of the
input, and that of the tracked layers below a cut. Under the cut, each gradient equals
the gradient that the rule of ticket 10 gives.

1. A suppressed first skip (`ignore_first_residual`) with an untracked first layer,
   under each scheme.
2. A suppressed last skip (`ignore_last_residual`) with an untracked top layer, under
   each scheme.
3. A cut inside the stack under MGR, where the streams differ at the start of the span.
   Use a `Schedule::Stretched` stack or a `GradHorizon::Mask`.
4. A span in which the accumulation phase ends: the stream count reaches `n_stream`
   inside the span.
5. MGR modules with `per_virtual_layer: true` across a cut.
6. The cases 1 to 5 through `step` and `prime`.

A case that fails gets its fix in this ticket. Put the fix in the residual join or in
the carry methods of the scheme. If a fix must change the owner of the backend hop,
write the reason in this ticket.

**Stop point: cases 1 and 2.** Under the rule of ticket 10, the carry path across a
suppressed skip has gain 0. So the input gets no gradient across the span. Write the
tests, record their results in this ticket, and ask the user to select one option:

- (i) Keep the carry. The input trains, and the carry is not exact there. The docs name
  the exception.
- (ii) Follow the rule. The gain is 0, and the input gets no gradient across the span.
- (iii) Reject the setting with a panic in `grad_tracked`, as it rejects untied tensors
  in an untracked layer. A parameter would otherwise silently not train. This is the
  recommended default.

Do not implement cases 1 and 2 before the user selects an option.

**Acceptance criteria:**

- [x] Each of the cases 3 to 6 has an exactness test that passes.
- [x] The cases 1 and 2 have tests for the option that the user selected, and the tests

- [x] The doc of `Layers::grad_horizon` and ADR-0006 give the rule of each edge case.
      They describe the code as it is.

**Constraints:**

- burn-mamba builds against its pin. Do not enable the `[patch]` of burn-mamba.

**Benches:** none.

**Out of scope:**

## Comments

> *This was generated by AI during the implementation of ticket 10.*

Ticket 10 leaves these choices for cases 1 and 2:

- A suppressed skip in a span keeps the gain of each carry path. So the code of
  ticket 10 is option (i) now. The module header of `src/modules/residuals.rs` states
  it.
- A suppressed first skip sets the aggregator weights `alpha` of `ResidualStreams` to
  `None`, because the token is the one stream `F_0` there.
- A span in which no join pools is a span of one layer with a suppressed skip. Under
  a suppressed last skip at the top, the token at the cut gets `Σᵢ αᵢ · carryᵢ`. The
  weights `αᵢ` come from the pool below the span, so each MGR pool keeps `alpha` in the
  value, also outside a span. With option (iii), no span has such a layer. Then
  `alpha` can live only inside a span.
- No test runs the `None` arm of the straight-through carry of the token in
  `Residuals::close_span`. A test of case 1 with a span of only the first layer runs
  it.

### Implementation notes

> *This was generated by AI during implementation.*

Probe results of cases 1 and 2 (`tmp/arb11/probe-suppressed-skips.log`, code in
`tmp/arb11/probes.rs`). Zero transforms, both schemes, each call. With no cut, the
input gets exactly 0. In case 2, each tracked layer below the span also gets exactly
0. Under the cut, the code of ticket 10 gives them gradients from 0.13 to 35.

A new finding of case 3 (`tmp/arb11/probe-w-alpha.log`): under MGR, the aggregator
query `w_alpha` of a tracked layer directly below a span gets no gradient. Its pooled
token only feeds the untracked transforms. With `Schedule::Stretched`, 8 virtual over
3 real layers and `Depth(1)`, `w_alpha` of modules 0 and 1 never trains.

Decisions of the user:

1. Cases 1 and 2: option (iii). `grad_tracked` panics when `ignore_first_residual`
   leaves virtual layer 0 untracked, or `ignore_last_residual` leaves the top layer
   untracked. Then each span pools, so `alpha` lives only inside a span, and
   `close_span` loses its `None` arm.
2. The `w_alpha` finding: a panic in this ticket, with its full scope. `grad_tracked`
   panics when an MGR module pools in a tracked layer, but no such layer feeds a
   tracked layer or the stack output. A module with no tracked pool does not panic
   (the truncation of `GradHorizon::last`). Under MGR with no weight sharing, or with
   `per_virtual_layer: true`, only a bottom span is then allowed.
3. The two panics reject configs that ran before, so the version is 0.43.0.

The code:

- `Residuals::assert_horizon_keeps_gradients` (`src/modules/residuals.rs`) holds both
  checks.
  `Layers::grad_tracked` calls it with the `JoinAt` of each virtual layer, after the
  untied check. The suppressed-skip check comes first, so a stack that breaks both
  rules gets its message. The checks run only on the autodiff backend, so a decode
  with the horizon of a training config does not panic.
- `alpha` lives only inside a span. A pool outside a span leaves it `None`.
  `open_span` asserts that it is `None`, and `close_span` takes it with an `expect`.
  So the `None` arm of the straight-through carry of the token is gone. The
  suppressed-skip arms of the join share one branch, with a `debug_assert` that no
  span holds them.
- The owner of the backend hop does not change.

The tests (`src/reference/tests/grad_horizon.rs`):

- `assert_zero_transform_span_is_exact` takes a `ZeroTransformSpan` (stack, mask,
  `UntrackedGates`) and a `Call` (`Forward`, `Step`, `Prime`). It compares the
  gradient of the input (the class latent in the prime). It also compares the
  gradients of each tracked real layer and of its MGR module.
  `UntrackedGates::Alternating` gives the modules of a span different gates.
- Cases 3, 4 and 5 each have one test that loops over the three calls. That loop is
  case 6. The stacks share real layers, because the `w_alpha` panic rejects a span
  above a tracked layer whose module pools only there:
  - case 3: 2 real layers, `Custom([0, 0, 1, 1, 0, 0, 1])`, mask
    `[T, T, F, F, T, T, F]`. A span inside the stack and a span at the top.
  - case 4: 2 real layers, `Custom([0, 1, 1, 0, 0, 0])`, mask `[T, F, F, T, T, T]`,
    3 streams. The span appends the third stream, then mixes.
  - case 5: per-virtual modules, `Custom([1, 1, 1, 0, 0, 0])`, mask
    `[F, F, F, T, T, T]`, alternating gates. Per-virtual modules allow only a bottom
    span.
- Cases 1 and 2: `grad_horizon_refuses_a_suppressed_skip_at_an_untracked_end_layer`
  runs each case with a span of one layer and of two layers, under both schemes, in
  each call (`catch_unwind`). `an_untracked_span_next_to_a_tracked_suppressed_skip_is_exact`
  tests the setting that stays allowed: `ignore: (true, true)`, mask `[T, F, F, T]`.
- The `w_alpha` panic: `grad_horizon_refuses_a_multi_gate_pool_that_feeds_only_untracked_layers`
  runs a span inside a stack with no sharing, per-virtual modules, and Stretched
  under `Depth(1)`, in each call.
- `grad_horizon_mask_alternates_and_keeps_forward_step_parity` moves to 3 real
  layers, 8 virtual, `Cyclic`, mask `[T, T, F, T, T, F, T, T]`, under both schemes.
  Its MGR arm with no sharing panics now. A real layer gets a gradient exactly when
  the mask tracks one of its applications.
- No other test changes an expected value or a tolerance.

The red runs:

- Before the panics, each panic test failed with "the run does not panic".
- Cases 3, 4 and 5 passed with no fix. Two mutations of `close_span` fail them:
  - "only the seed stream gets a straight-through carry" (before the move, in each call),
  - "the gain of each carry path is 1" (after the move, each test with an open gate).

The review (`tmp/arb11/review-standards.md`, `tmp/arb11/review-spec.md`) found no
error in the checks. The fixes after it:

- The docs said that MGR with no sharing allows only a bottom span. A span directly
  above a suppressed first skip is also allowed, because layer 0 does not pool. The
  doc of `Layers::grad_horizon` and ADR-0006 now say so. They also name
  `per_virtual_layer` (case 5), and the refusal of `Schedule::Stretched` + `Depth(1)`:
  it panics when a run other than the bottom one is longer than one layer.
- Two docs of `Layers` said that a mask can turn off and on "arbitrarily". They now
  say that the panics limit where a span can be.
- The check is `assert_horizon_keeps_gradients`, not `assert_horizon_trains`. Its doc
  names its two settings. `JoinAt::suppressed` replaces three copies of
  `at.first || at.last`.
- The tests: `utils::test_helpers::panic_text` holds the payload `match`, and
  `run_contract` of the block contracts uses it too. `Layers::real_idx` is
  `pub(crate)`, so `parts_of` reads it. `identity_grad` and `assert_exact_in_each_call`
  are separate helpers. The two panic tests point to the doc of the check, and do
  not copy it.
- Review items that stay (judgement calls): the `ignore: (bool, bool)` tuple of
  `ZeroTransformSpan`, the two index lists of `ZeroTransformSpan::stack`, and the two
  slices of `assert_horizon_keeps_gradients`.
