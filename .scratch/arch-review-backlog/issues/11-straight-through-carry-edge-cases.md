# 11: The edge cases of the straight-through carry

Status: ready-for-agent

Blocked by: `10-mgr-straight-through-carry.md`

> *This was generated by AI during triage.*

From the triage of `02-residuals-transition.md` on 2026-11-16. Ticket 10 sets the rule
of the straight-through carry for the main case. This ticket tests that rule in each
edge case and fixes each case that fails. It stops at the suppressed skips, because
the user selects their rule.

## Agent brief

**Category:** bug

**Summary:** Test the straight-through carry in each edge case against the rule of
ticket 10, and fix each case that fails. Stop at the suppressed skips for a decision
of the user.

**Current behaviour:**

- After ticket 10, the exactness tests of the gradient horizon cover a cut at the
  bottom of the stack, with closed and with open gates.
- No test runs a cut together with `ignore_first_residual` or `ignore_last_residual`.
- No exactness test runs these cases:
  - a cut inside the stack under MGR
  - a span in which the accumulation phase ends
  - `per_virtual_layer` modules across a cut
  - the cascade of `step` and `prime` under a cut

  Some of them run in tests that compare values and check only that a gradient exists,
  for example `grad_horizon_mask_alternates_and_keeps_forward_step_parity`.

**Desired behaviour:**

Each case below gets one exactness test in the style of `assert_identity_span_is_exact`.
The untracked layers have zero transforms. The test compares two gradients: that of the
input, and that of the tracked layers below a cut. Under the cut, each gradient equals
the gradient that the rule of ticket 10 gives.

1. A suppressed first skip (`ignore_first_residual`) with an untracked first layer,
   under each scheme.
2. A suppressed last skip (`ignore_last_residual`) with an untracked top layer, under
   each scheme.
3. A cut inside the stack under MGR, where the streams differ at the start of the span.
   Use a `Schedule::Stretched` stack or a `GradHorizon::Mask`.
4. A span in which the accumulation phase ends: the stream count reaches `n_stream`
   inside the span.
5. MGR modules with `per_virtual_layer: true` across a cut.
6. The cases 1 to 5 through `step` and `prime`.

A case that fails gets its fix in this ticket. Put the fix in the residual join or in
the carry methods of the scheme. If a fix must change the owner of the backend hop,
write the reason in this ticket.

**Stop point: cases 1 and 2.** Under the rule of ticket 10, the carry path across a
suppressed skip has gain 0. So the input gets no gradient across the span. Write the
tests, record their results in this ticket, and ask the user to select one option:

- (i) Keep the carry. The input trains, and the carry is not exact there. The docs name
  the exception.
- (ii) Follow the rule. The gain is 0, and the input gets no gradient across the span.
- (iii) Reject the setting with a panic in `grad_tracked`, as it rejects untied tensors
  in an untracked layer. A parameter would otherwise silently not train. This is the
  recommended default.

Do not implement cases 1 and 2 before the user selects an option.

**Acceptance criteria:**

- [ ] Each of the cases 3 to 6 has an exactness test that passes.
- [ ] The cases 1 and 2 have tests for the option that the user selected, and the tests
      pass.
- [ ] Each fix has a test that fails before the fix.
- [ ] Coverage: run `scripts/coverage.py --base BASE`, with `BASE` = the last commit of
      ticket 10. Copy the result into a **Coverage result** section of this ticket. The
      branch and condition coverage of `residuals.rs` and `layers.rs` goes up, and no
      item is lost.
- [ ] The checks and tests of this repo pass, as `CLAUDE.md` gives them, with no
      warnings.
- [ ] The doc of `Layers::grad_horizon` and ADR-0006 give the rule of each edge case.
      They describe the code as it is.

**Constraints:**

- burn-mamba builds against its pin. Do not enable the `[patch]` of burn-mamba.

**Benches:** none.

**Out of scope:**

- The main rule of MGR: ticket 10.
- `BidiLayers`. It has no gradient horizon.
- A new residual scheme.

## Comments

> *This was generated by AI during the implementation of ticket 10.*

Ticket 10 leaves these choices for cases 1 and 2:

- A suppressed skip in a span keeps the gain of each carry path. So the code of
  ticket 10 is option (i) now. The module header of `src/modules/residuals.rs` states
  it.
- A suppressed first skip sets the aggregator weights `alpha` of `ResidualStreams` to
  `None`, because the token is the one stream `F_0` there.
- A span in which no join pools is a span of one layer with a suppressed skip. Under
  a suppressed last skip at the top, the token at the cut gets `Σᵢ αᵢ · carryᵢ`. The
  weights `αᵢ` come from the pool below the span, so each MGR pool keeps `alpha` in the
  value, also outside a span. With option (iii), no span has such a layer. Then
  `alpha` can live only inside a span.
- No test runs the `None` arm of the straight-through carry of the token in
  `Residuals::close_span`. A test of case 1 with a span of only the first layer runs
  it.
