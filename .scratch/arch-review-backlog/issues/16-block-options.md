# 16: The options of a block are a setting of the block

Status: needs-triage

Priority: low

Blocked by: None

From the architecture review of 2026-11-16. Line numbers are those of burn-stack
commit `b198fa5` and burn-mamba commit `7807d31b`. Speculative. The review compiled
nothing.

**Files:** `src/modules/mod.rs` (`Block::Options`, `reset_align`), the `options`
parameter of each forward in `src/modules/{layer,layers,network,bidi}.rs` and
`src/modules/hnet/`, `../burn-mamba/src/family/mod.rs:82-112` (`MambaSsdPath`),
`../burn-mamba/src/family/block.rs:76-132`.

**Problem:** Each forward of each container passes `options` to the next module, with
the bound `M::Options: Clone`. `step` and `prime` take none. In the examples, the
value is a constant of the run (`Run::ssd_path`). The run-time family choice adds the
enum `MambaSsdPath` and 5 functions that extract the path of one family. It also adds
a panic for a path of the wrong family. One `Options` value also makes a mixed stack
panic (ADR-0009 of burn-mamba).

**Direction:** The block holds its options as a non-parameter field, as `Layers` holds
`grad_horizon`. `Block::Options`, the `options` parameters and `MambaSsdPath` go, and
`reset_align` takes no argument.

**Cost, and why this is speculative:**

- A caller needs a way to set the field on each block of a container. That is a new
  interface in each container.
- The agreement tests compare SSD paths on one set of weights. They must clone the
  block for each path.

**First:** Do `../burn-mamba/.scratch/arch-review-backlog/issues/18-pathway-option.md`,
which moves the pathway into the options. Then look at how callers use the options.

Split this ticket by repo at triage.

## Comments

### Names after burn-mamba ticket 22

> *This was generated by AI during the triage of burn-mamba ticket 22.*

`../burn-mamba/.scratch/arch-review-backlog/issues/22-ssd-path-struct.md` renames the
types of this ticket:

- `MambaSsdPath` is `MambaScanOptions`. The options of each family are
  `Mamba2ScanOptions` and `Mamba3ScanOptions`.
- These three types derive `Config`. So a block can hold them as a field, and a record
  of a run can save them.
- The glossary of burn-mamba calls them **Scan options**: the SSD path and the chunk
  length.

The order of the burn-mamba tickets is 22, then 18, then this ticket.

### Names after ticket 12

> *This was generated by AI during the triage of ticket 12.*

The maintainer accepted ticket 12 (`12-one-cache-stack.md`) and its burn-mamba half,
`../burn-mamba/.scratch/arch-review-backlog/issues/23-one-cache-stack.md`. Both land
before this ticket, because they change the same signatures. After them:

- `Block` has no associated type `Caches`. Its calls take the cache with no `Option`:
  `block_forward(&self, x, cache: Self::Cache, options, pad)`,
  `block_forward_packed(&self, x, cache: Self::Cache, options, reset)` and
  `block_step(&self, x, cache: Self::Cache)`.
- `Layer::forward`, `Layer::forward_packed` and `Layer::step` take `M::Cache`.
- The containers take `Option<Vec<M::Cache>>`, and return `Vec<M::Cache>`. `HNet`
  and `HNetVocabNetwork` take `Option<HNetCaches<E, M>>`.
- So the `options` parameter is the only change of these signatures that remains for
  this ticket.
